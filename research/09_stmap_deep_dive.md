## 1. What is an STMap?

An **ST Map** (also written as STMap) is an image-based deformation map used for lens distortion correction in visual effects and virtual production workflows.

### Definition

An ST Map is an image in which the value of each pixel corresponds to a distorted image coordinate in UV space. Specifically:

- **Red channel (S)**: Contains the X coordinate (horizontal) of where the source pixel should be sampled
- **Green channel (T)**: Contains the Y coordinate (vertical) of where the source pixel should be sampled
- **Blue channel**: Typically unused or set to zero

The name "ST" comes from texture mapping conventions where S and T represent the horizontal and vertical texture coordinates (analogous to U and V in UV mapping).

### How It Works

When applying an STMap to an image:
1. For each pixel in the output image, read the STMap's R and G values
2. These values represent normalized UV coordinates (typically 0.0-1.0 range)
3. Sample the source image at those UV coordinates
4. The result is a warped/distorted version of the source image

## 2. STMap Format Technical Details

### Image Format Requirements

| Attribute | Requirement |
|-----------|-------------|
| **Bit Depth** | Minimum 16-bit per channel (half-float or full float EXR preferred) |
| **Color Space** | Linear (no gamma correction) |
| **Channels** | RGB (Red=S, Green=T, Blue=unused) |
| **Value Range** | Normalized 0.0-1.0 (or 0-255 for 8-bit, but not recommended) |
| **File Format** | EXR (preferred), TIFF (16-bit with "raw data" option), PNG |

### Coordinate System

The STMap uses normalized coordinates where:
- `(0.0, 0.0)` = top-left corner
- `(1.0, 1.0)` = bottom-right corner
- `(0.5, 0.5)` = center of image

**Important:** When generating STMaps, add 0.5 to pixel coordinates before dividing by width/height to account for pixel center offset:

```
S = (x + 0.5) / width
T = (y + 0.5) / height
```

## 3. How STMaps Are Generated from Lens Calibration Data

### Mathematical Foundation

STMaps are generated by computing the **forward or backward mapping** between distorted and undistorted image coordinates:

#### Forward Mapping (Distortion)
Takes undistorted coordinates and computes where they map in the distorted image:
```
distorted_coord = distort(undistorted_coord, K, D)
```

#### Backward Mapping (Undistortion) 
Takes distorted coordinates and computes where they came from in the undistorted image:
```
undistorted_coord = undistort(distorted_coord, K, D)
```

Where:
- `K` = Camera matrix (intrinsics)
- `D` = Distortion coefficients

### Generation Process

1. **Create base coordinate image**: Generate an image where each pixel contains its own normalized coordinates
2. **Apply lens model**: Use the calibrated lens parameters to warp these coordinates
3. **Save as STMap**: The warped coordinates become the STMap

### Two Types of STMaps

| Type | Purpose | Description |
|------|---------|-------------|
| **Undistortion Map** | Remove lens distortion from plates | Maps distorted pixels to their undistorted positions |
| **Redistortion Map** | Add lens distortion to CG elements | Maps undistorted pixels to their distorted positions |

## 4. STMap Resolution Requirements

### General Guidelines

The STMap resolution determines the precision of the distortion correction:

| Use Case | Recommended Resolution | Notes |
|----------|----------------------|-------|
| **Preview/Proxy** | 512x512 to 1024x1024 | Fast processing, lower quality |
| **Standard HD** | 1920x1080 or higher | Matches plate resolution |
| **4K/UHD** | 3840x2160 or higher | Matches plate resolution |
| **High-precision VFX** | 2x plate resolution | Better subpixel accuracy |

### Unreal Engine Specific

In Unreal Engine's Camera Calibration plugin:

- The **displacement map resolution** can be specified in project settings
- Default is relatively small compared to final render resolution (e.g., 128x128)
- The displacement map is used to generate the post-process material
- Higher resolution maps provide more accurate distortion but require more memory

**Key Point:** The displacement map resolution in UE does not need to match the render resolution because the distortion is applied as a post-process effect using texture sampling.

**Source:** Epic Games Documentation - Camera Lens Calibration Overview  
**URL:** https://dev.epicgames.com/documentation/en-us/unreal-engine/camera-lens-calibration-overview

### Bit Depth Considerations

- **8-bit**: Insufficient precision, causes visible banding artifacts
- **16-bit (half-float)**: Minimum recommended for production
- **32-bit (full float)**: Best quality, larger file size

## 5. Unreal Engine LensFile System and STMap Import

### LensFile Asset

The Camera Calibration plugin introduces the **Lens File asset type** which encapsulates all calibration data:

- Distortion parameters (K1, K2, P1, P2, K3)
- Camera intrinsics (focal length, image center)
- Nodal point offset
- **ST Maps** (for external calibration data)

### STMap Import Process

1. **Enable Camera Calibration plugin** in your project
2. **Create a Lens File asset** (Right-click → Create Advanced Asset → Camera Calibration → Lens File)
3. **Open the Lens File Asset Editor**
4. **Import ST Maps** for specific focus/zoom positions
5. **Configure interpolation** between calibrated points

### Supported Input Methods

The Lens File supports three primary types of distortion input:

1. **Live Link Lens source** - Streaming per-frame distortion parameters
2. **Live Link Camera FIZ** - Streaming focus/iris/zoom to evaluate Lens File
3. **Direct ST Map input** - Pre-calculated distortion maps from external tools

### STMap Interpolation

When a Lens File contains ST Maps:
- Maps are interpolated based on incoming focus and zoom values
- The system interpolates between the closest calibrated focus/zoom points
- This allows smooth distortion changes during camera moves

**Source:** Epic Games Documentation - Camera Lens Calibration Overview  
**URL:** https://dev.epicgames.com/documentation/en-us/unreal-engine/camera-lens-calibration-overview

### Distortion Pipeline in UE

```
Input Data → Lens Distortion Handler → UV Displacement Map → Post-Process Material → Distorted Output
```

The lens distortion handler:
1. Receives distortion parameters and camera intrinsics
2. Generates a distortion UV displacement map
3. Creates a post-process material referencing the displacement map
4. Consumers (CineCamera, Composure CG layers) apply the effect

**Source:** Epic Games Documentation - Camera Lens Calibration Overview  
**URL:** https://dev.epicgames.com/documentation/en-us/unreal-engine/camera-lens-calibration-overview

## 6. STMap vs Parametric Distortion: Pros and Cons

### Parametric Distortion (Brown-Conrady Model)

Uses mathematical coefficients (K1, K2, K3, P1, P2) to describe lens distortion.

**Pros:**
- ✅ Smaller file size (just 5-10 coefficients vs. full image)
- ✅ Easy to animate/interpolate between different focal lengths
- ✅ Mathematically precise for standard lens models
- ✅ Works well with zoom and focus changes
- ✅ Industry standard, widely supported
- ✅ Can be adjusted/tweaked by modifying coefficients

**Cons:**
- ❌ Limited to specific lens models (may not capture complex distortions)
- ❌ Different software uses different models (compatibility issues)
- ❌ Cannot represent non-standard or asymmetric distortions
- ❌ Requires precise calibration to get accurate coefficients

### STMap-Based Distortion

Uses image-based deformation maps to describe lens distortion.

**Pros:**
- ✅ Software-agnostic (works in any app supporting image warping)
- ✅ Can represent any distortion, including complex/asymmetric
- ✅ No mathematical model limitations
- ✅ Easy to exchange between different software packages
- ✅ Can be generated from any calibration tool
- ✅ Captures real-world lens characteristics precisely

**Cons:**
- ❌ Large file size (full image per focal length)
- ❌ Difficult to interpolate between different focal lengths
- ❌ Cannot easily animate changing distortion
- ❌ Requires high bit depth to avoid artifacts
- ❌ Must generate separate maps for undistort and redistort operations
- ❌ Zooming/focusing requires multiple maps and interpolation

### When to Use Each

| Scenario | Recommended Approach |
|----------|-------------------|
| Fixed focal length, complex distortion | STMap |
| Zoom lenses, changing focus | Parametric |
| Multi-software pipeline | STMap |
| Real-time virtual production | Parametric (performance) |
| Matchmoving → Compositing exchange | STMap |
| High-precision VFX | STMap (with overscan) |

## 7. Generating STMaps from OpenCV Calibration Data (Python)

### OpenCV Lens Models

OpenCV supports two main lens models:

1. **Standard Model** (Brown-Conrady): Uses coefficients `[k1, k2, p1, p2, k3]`
2. **Fisheye Model**: Uses coefficients `[k1, k2, k3, k4]` for wide-angle lenses

### Python Implementation

Below is a complete implementation based on the Gyroflow stmap-undistort repository:

```python
import numpy as np
import imageio
import cv2
import json

class LensSTMapGenerator:
    """
    Generate STMaps from OpenCV calibration data for use in Unreal Engine/Nuke
    """
    
    def __init__(self):
        self.K = None  # Camera matrix
        self.D = None  # Distortion coefficients
        self.calib_dimension = None
        self.orig_dimension = None
    
    def load_opencv_calibration(self, json_file):
        """
        Load calibration from OpenCV-style JSON format
        
        Expected format:
        {
            "camera_matrix": [[fx, 0, cx], [0, fy, cy], [0, 0, 1]],
            "distortion_coeffs": [k1, k2, p1, p2, k3],
            "image_width": 1920,
            "image_height": 1080
        }
        """
        with open(json_file, "r") as f:
            cal_data = json.load(f)
        
        self.K = np.array(cal_data["camera_matrix"])
        self.D = np.array(cal_data["distortion_coeffs"])
        self.calib_dimension = (cal_data["image_width"], cal_data["image_height"])
        self.orig_dimension = self.calib_dimension
        
        print(f"Loaded calibration: {self.calib_dimension}")
        print(f"Camera matrix:\n{self.K}")
        print(f"Distortion coefficients: {self.D}")
    
    def generate_base_stmap(self, width, height):
        """
        Generate base STMap with normalized coordinates
        
        Returns S and T channels where:
        - S (Red) = normalized X coordinate
        - T (Green) = normalized Y coordinate
        """
        # Create coordinate arrays
        x_coords = np.arange(width)
        y_coords = np.arange(height)
        
        # Create meshgrid
        X, Y = np.meshgrid(x_coords, y_coords)
        
        # Normalize coordinates (add 0.5 for pixel center offset)
        S = (X + 0.5) / width   # Red channel
        T = (Y + 0.5) / height  # Green channel
        
        return S, T
    
    def generate_undistort_stmap(self, fov_scale=1.0):
        """
        Generate STMap for undistorting images
        
        This map takes distorted coordinates and maps them to 
        their undistorted positions.
        """
        width, height = self.calib_dimension
        
        # Create input map with pixel coordinates
        inmap = np.zeros((height, width, 2), dtype=np.float32)
        inmap[:,:,0] = np.repeat(np.arange(width)[None,:], height, 0)
        inmap[:,:,1] = np.repeat(np.arange(height)[None,:], width, 0).T
        
        # Get optimal new camera matrix
        new_K, roi = cv2.getOptimalNewCameraMatrix(
            self.K, self.D, (width, height), 
            alpha=fov_scale, newImgSize=(width, height),
            centerPrincipalPoint=True
        )
        
        # Undistort the coordinate points
        undistorted = cv2.undistortPoints(
            inmap.reshape(-1, 1, 2), 
            self.K, self.D, 
            None, new_K
        )
        
        undistorted = undistorted.reshape(height, width, 2)
        
        # Extract S and T channels
        S = undistorted[:,:,0] / width
        T = undistorted[:,:,1] / height
        
        return S, T
    
    def generate_distort_stmap(self, fov_scale=1.0):
        """
        Generate STMap for distorting images (redistortion)
        
        This map takes undistorted coordinates and maps them to
        their distorted positions.
        """
        width, height = self.calib_dimension
        
        # Get optimal new camera matrix
        new_K, roi = cv2.getOptimalNewCameraMatrix(
            self.K, self.D, (width, height),
            alpha=fov_scale, newImgSize=(width, height),
            centerPrincipalPoint=True
        )
        
        # Initialize undistort rectify maps
        # map1 gives us the mapping from distorted to undistorted
        map1, map2 = cv2.initUndistortRectifyMap(
            self.K, self.D, None, new_K, 
            (width, height), cv2.CV_32FC1
        )
        
        # Normalize to 0-1 range
        S = map1 / width
        T = map2 / height
        
        return S, T
    
    def save_stmap_exr(self, S, T, output_path):
        """
        Save STMap as EXR file with proper format
        
        Channels:
        - Red (S): X coordinate mapping
        - Green (T): Y coordinate mapping  
        - Blue: Zero (unused)
        """
        # Stack channels (flip vertically for proper orientation)
        rgb = np.dstack((S, T, np.zeros_like(S)))
        rgb = np.flip(rgb, 0)
        
        # Save as EXR
        imageio.imwrite(output_path, rgb)
        print(f"STMap saved to: {output_path}")
    
    def save_stmap_unreal(self, S, T, output_path):
        """
        Save STMap in format optimized for Unreal Engine
        
        UE expects STMaps with specific coordinate conventions
        """
        # UE may expect different coordinate orientation
        # Test and adjust as needed
        rgb = np.dstack((S, T, np.zeros_like(S)))
        
        # Some versions of UE expect flipped Y
        # rgb = np.flip(rgb, 0)
        
        imageio.imwrite(output_path, rgb)
        print(f"STMap (UE format) saved to: {output_path}")


# Example usage
if __name__ == "__main__":
    generator = LensSTMapGenerator()
    
    # Load calibration data
    generator.load_opencv_calibration("calibration_data.json")
    
    # Generate undistortion map
    S_undist, T_undist = generator.generate_undistort_stmap(fov_scale=0)
    generator.save_stmap_exr(S_undist, T_undist, "undistort_map.exr")
    
    # Generate redistortion map
    S_dist, T_dist = generator.generate_distort_stmap(fov_scale=0)
    generator.save_stmap_exr(S_dist, T_dist, "distort_map.exr")
```

## 8. Nuke STMap Workflow

### Nuke STMap Node

The STMap node in Nuke applies distortion using an STMap image:

**Inputs:**
- **Source**: The image to be distorted
- **STMap**: The distortion map (Red=S, Green=T)

**Parameters:**
- **uv channels**: Which channels contain the ST coordinates (default: rgb)
- **filter**: Interpolation filter (Cubic recommended for quality)

### Creating STMaps in Nuke

#### Method 1: From LensDistortion Node

```
1. Create a LensDistortion node
2. Calibrate using grid footage or set coefficients manually
3. Create a Constant node matching your plate size
4. Add an Expression node with:
   - r = (x+0.5)/width
   - g = (y+0.5)/height
5. Pipe through LensDistortion node
6. Write out as EXR (16-bit or float, linear)
```

#### Method 2: From UV Map

```
1. Create UV map using Expression node:
   - r = (x+0.5)/width
   - g = (y+0.5)/height
2. Apply distortion using LensDistortion or IDistort
3. The result is your STMap
```

### Nuke STMap Workflow Steps

**For Undistorting Plates:**
```
Original Plate → STMap Node (with undistort map) → Undistorted Plate (larger size)
```

**For Distorting CG Elements:**
```
CG Render → STMap Node (with distort map) → Reformat (to plate size) → Distorted CG
```

**Source:** VFX Rants Blog - Using STMap based deformations for Lens Distortion workflow  
**URL:** http://vfx-rants.blogspot.com/2013/07/using-stmap-based-deformations-for-lens.html

### Important Nuke Considerations

1. **Bit Depth**: Always use 16-bit or float EXR for STMaps
2. **Color Space**: Ensure linear color space (no gamma)
3. **Overscan**: Undistorted plates will be larger than original
4. **Reformat**: When redistorting CG, use "type: to format" with "resize type: none, centered"

## 9. Nuke to Unreal Engine Workflow

### Workflow Overview

```
Lens Grid Footage → Nuke (LensDistortion) → STMap → Unreal Engine (LensFile)
```

### Step-by-Step Process

1. **Film Lens Grid**
   - Use a checkerboard or dot pattern
   - Film at multiple focus and zoom positions
   - Ensure good coverage and sharp focus

2. **Calibrate in Nuke**
   - Use LensDistortion node with "Grid" analysis
   - Or use 3DEqualizer/SynthEyes and export to Nuke

3. **Generate STMaps**
   - Create undistort and distort STMaps
   - Export as 16-bit or float EXR
   - Name clearly with lens/focal length info

4. **Import to Unreal Engine**
   - Create Lens File asset
   - Import STMaps for each calibrated focus/zoom point
   - Set up interpolation between points

5. **Configure in UE**
   - Assign Lens File to CineCamera
   - Set up Live Link for real-time FIZ data
   - Configure Composure CG layers with distortion

### File Format Compatibility

| Software | Preferred Format | Notes |
|----------|-----------------|-------|
| Nuke | EXR (half-float) | Linear color space |
| Unreal Engine | EXR, PNG | Import via Lens File |
| Fusion | EXR, TIFF | Similar workflow to Nuke |
| After Effects | EXR | Via third-party plugins |

## 10. Key Implementation Considerations

### Coordinate System Differences

Different software may use different coordinate conventions:

| Software | Y-Axis Direction | UV Range | Notes |
|----------|-----------------|----------|-------|
| Nuke | Bottom-up | 0-1 | Standard STMap |
| Unreal Engine | Top-down | 0-1 | May need Y-flip |
| OpenCV | Top-down | Pixel coords | Normalize before export |

**Important:** When STMaps don't align correctly between software, try flipping the Y-axis (vertical flip).

### Overscan Requirements

When undistorting an image:
- The resulting image will be **larger** than the original
- This is because corners of the image move outward
- The overscan factor depends on the amount of distortion
- In UE, the overscan is computed automatically by the lens distortion handler

### Alpha Channel Considerations

When using `cv2.getOptimalNewCameraMatrix()`:
- `alpha=0`: Returns undistorted image with all valid pixels (may have black borders)
- `alpha=1`: Returns undistorted image with all original pixels (may crop some valid data)
- Intermediate values: Trade-off between cropping and black borders

**Source:** Agisoft Forum - Matching ST Map and OpenCV Undistortion  
**URL:** https://www.agisoft.com/forum/index.php?topic=15977.0

### Performance Considerations

**In Unreal Engine:**
- STMap-based distortion requires texture sampling
- Parametric distortion is computed on-the-fly
- For real-time VP, parametric may be faster
- For pre-rendered, STMap provides better quality

**In Compositing:**
- STMap nodes are GPU-accelerated in most software
- High-resolution STMaps use more memory
- Consider proxy STMaps for interactive work

### Common Issues and Solutions

| Issue | Cause | Solution |
|-------|-------|----------|
| STMap doesn't align | Coordinate system mismatch | Try flipping Y-axis |
| Banding artifacts | 8-bit STMap | Use 16-bit or float EXR |
| Black edges | Insufficient overscan | Increase fov_scale/alpha |
| Soft/distorted edges | Filter settings | Use Cubic filter in Nuke |
| Color shift | Wrong color space | Ensure linear, no gamma |

## Summary

STMaps provide a powerful, software-agnostic method for lens distortion correction in virtual production workflows. Key takeaways:

1. **STMaps are coordinate maps** (Red=S/X, Green=T/Y) that define pixel displacement
2. **High bit depth is essential** - use 16-bit or float EXR
3. **Two maps needed**: One for undistortion, one for redistortion
4. **Unreal Engine supports STMaps** via the LensFile asset system
5. **Python/OpenCV can generate STMaps** from calibration data
6. **Nuke workflow is well-established** and can feed into UE
7. **Coordinate system differences** may require Y-flipping between software
